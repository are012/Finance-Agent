# Korea Equity Backtest Strategy Research Design

작성일: 2026-06-02

## 1. 요약

이 문서는 특정 종목 매수 추천이 아니라 한국 KOSPI/KOSDAQ 시장에서 실거래 가능성이 높은 백테스트 전략 후보를 설계하기 위한 연구 산출물이다. 목표는 높은 누적수익률을 찾아내는 것이 아니라 비용 차감 후에도 설명 가능하고, 과최적화 가능성이 낮고, 유동성·체결·시장제약을 반영해도 무너지지 않는 전략 후보를 선별하는 것이다.

가장 먼저 검증할 전략은 다음 2개다.

1. **시장 국면 필터 + 거래대금 필터 + 중기 상대강도 모멘텀**
   - 일봉 기반, 주간 리밸런싱, long-only.
   - KOSPI/KOSDAQ을 분리해 유동성 상위 보통주만 편입한다.
   - 지수 추세가 약하면 신규 매수를 중단하거나 현금 비중을 높인다.
   - 장점: 규칙이 단순하고 설명 가능하며, 체결 가정을 보수적으로 넣어도 구현이 쉽다.
   - 핵심 리스크: 모멘텀 급반전, 특정 성장주 장세 편향, KOSDAQ 소형주 유동성 과대평가.

2. **국내 상장 ETF 기반 방어형 자산배분**
   - KOSPI200/KOSDAQ150/단기채 또는 현금성 ETF를 이용한 월간 리밸런싱.
   - 개별 종목 생존자 편향과 거래정지 문제를 크게 줄이는 방어적 기준 전략이다.
   - 장점: 실거래 재현성이 높고 체결 가능성이 상대적으로 좋다.
   - 핵심 리스크: 개별주 알파가 제한적이고, ETF 보수·추적오차·괴리율을 별도 반영해야 한다.

이 두 전략이 우선인 이유는 파라미터 수가 적고, 일봉 데이터로 구현 가능하며, 개인 또는 소규모 자동매매 시스템이 다음 거래일 시가/VWAP 주문으로 재현하기 쉽기 때문이다. 변동성 돌파나 단기 평균회귀 전략은 후보에는 포함하되, 한국 시장의 거래세·슬리피지·상한가/하한가 체결 실패에 더 민감하므로 1차 실험의 보조 후보로 둔다.

## 2. 시장 특성 분석

### 2.1 기준 시장과 거래 세션

기본 연구 범위는 KRX 정규장 KOSPI/KOSDAQ 상장 보통주다. ETF 전략만 국내 상장 ETF를 별도 유니버스로 둔다. KRX 안내 기준으로 정규장 거래시간은 09:00-15:30이고, 장전/장후 시간외 세션이 별도로 존재한다. 초기 백테스트는 정규장 체결만 사용하고 시간외 거래는 사용하지 않는다. 시간외 데이터 품질과 유동성 편차가 커서 개인 자동매매 재현성을 과대평가할 수 있기 때문이다.

출처: KRX의 "Guide to Trading in the Korean Stock Market"는 정규장, 장전/장후 세션, 거래 단위, 가격제한폭, 결제, 호가단위 등을 요약한다. KRX 거래시간 페이지도 정규장 09:00-15:30 및 T+2 결제 완료 구조를 설명한다.

### 2.2 가격제한폭, 호가단위, 거래 단위

백테스트 엔진은 다음 값을 하드코딩하지 않고 `market_rules` 설정으로 관리한다.

| 항목 | 기본 모델 |
| --- | --- |
| 거래 단위 | 주식/ETF/ETN 1주 단위 |
| 가격제한폭 | 기준가 대비 일간 ±30% |
| 호가단위 | 가격 구간과 시장별로 다름. KOSPI는 100,000원 이상 구간에서 KOSDAQ보다 호가단위가 커진다. ETF/ETN/ELW는 가격과 무관하게 별도 호가단위 적용 |
| 체결 방식 | 정규장은 연속매매, 시가/종가는 단일가 매매 특성 반영 |
| 결제 | T+2 결제 구조 |

주문 가격은 반드시 호가단위로 반올림한다. 매수 주문은 불리한 방향으로 올림, 매도 주문은 불리한 방향으로 내림을 기본값으로 둔다. 이렇게 해야 호가단위 처리만으로 생기는 낙관 편향을 줄일 수 있다.

### 2.3 비용과 세금

매도 거래세와 농어촌특별세는 기간별·시장별 설정으로 관리한다. 2026년 현재 기준의 실거래 스트레스 테스트에는 다음 기본값을 사용한다.

| 시장 | 2026년 기본 매도 세금 모델 |
| --- | --- |
| KOSPI | 증권거래세 0.05% + 농어촌특별세 0.15% = 총 0.20% |
| KOSDAQ | 증권거래세 0.20% |

증권거래세법 시행규칙 개정문은 2026년 기준 유가증권시장 증권거래세 5/10,000, 코스닥시장 및 K-OTC 20/10,000을 명시한다. 농어촌특별세법 제5조는 대통령령으로 정하는 증권시장에서 거래된 증권 양도가액에 대해 15/10,000 세율을 둔다.

백테스트는 두 모드를 모두 돌린다.

1. **역사적 비용 모드:** 거래일 당시 세율·수수료·호가 규칙을 적용한다.
2. **현재 비용 스트레스 모드:** 2010년 이후 전체 기간에 2026년 현재 또는 더 보수적인 비용을 적용해 현재 실거래 가능성을 평가한다.

### 2.4 공매도, 시장 중단, 체결 불확실성

초기 전략은 long-only라 공매도를 사용하지 않는다. 다만 시장 국면 분석과 벤치마크 설명에는 공매도 제약을 기록한다. FSC는 2025년 3월 31일부터 주식 공매도를 전면 재개한다고 발표했고, 제도상 무차입 공매도 방지 시스템과 내부통제 요건을 강화했다. 따라서 short 전략은 별도 연구가 필요하며, 본 연구의 초기 후보에서는 제외한다.

서킷브레이커, VI, 동시호가, 상한가/하한가 잠김은 실제 체결 가능성을 크게 바꾼다. 일봉 데이터만 있을 때는 이를 완벽히 재현할 수 없으므로 다음 보수 규칙을 둔다.

- 다음 거래일 매수 대상이 상한가로 시작하고 장중 거래량이 부족하면 매수 실패 처리.
- 다음 거래일 매도 대상이 하한가로 시작하고 장중 거래량이 부족하면 매도 실패 또는 부분 체결 처리.
- 거래정지·관리종목·투자경고/위험종목은 신규 편입 금지.
- 이미 보유한 종목이 거래정지되면 평가손익은 유지하되 매도 불가 상태로 기록하고, 재개 후 보수적 슬리피지를 적용한다.
- 시장 전체 서킷브레이커 발생일은 신규 진입을 중단하고 청산 주문은 체결 가능성 검증 후 반영한다.

## 3. 전략 후보 목록

### 3.1 후보 A: 시장 국면 필터 + 상대강도 모멘텀

| 항목 | 설계 |
| --- | --- |
| 전략 가설 | 한국 시장에서도 중기 상대강도와 추세 지속 현상이 존재하지만, 약세장에서는 모멘텀 붕괴와 갭 하락이 커진다. 지수 추세 필터와 유동성 필터로 이를 완화한다. |
| 한국 시장 적합성 | KOSDAQ 소형주 과열과 급락 리스크가 크므로 시장 국면 필터가 필수다. 일봉 기반이라 개인 자동매매 구현이 쉽다. |
| 매수 조건 | KOSPI/KOSDAQ 보통주 중 최근 60거래일 평균 거래대금 상위, 거래정지·관리·투자경고 제외, 6개월 또는 12개월 수익률 상위, 단기 과열을 줄이기 위해 최근 5거래일 급등 종목 제외. |
| 매도 조건 | 순위 하락, 지수 추세 훼손, 개별 종목 20일 저가 이탈, 거래대금 필터 이탈, 위험종목 지정. |
| 리밸런싱 | 주간. 매주 첫 거래일에 전주 마지막 거래일 종가 신호를 사용해 다음 거래일 시가 또는 VWAP 체결. |
| 포지션 사이징 | 종목당 최대 5%, 포트폴리오 주식 비중 최대 80%, 변동성 역가중. 체결 주문은 일평균 거래대금의 1% 이하로 제한. |
| 손절/추세 이탈 | 개별 종목 20일 저가 또는 ATR 기반 손절. 지수 120일 이동평균 하회 시 신규 매수 중단. |
| 필요한 데이터 | 일봉 OHLCV, 수정주가, 거래대금, 상장/상장폐지 이력, 종목 상태 플래그, KOSPI/KOSDAQ 지수, 기업 이벤트. |
| 장점 | 단순하고 설명 가능하다. 거래 빈도가 중간 수준이라 비용 민감도가 관리 가능하다. |
| 약점 | 모멘텀 급반전과 특정 섹터 쏠림에 취약하다. 상승장에서는 좋아 보이나 횡보장에서는 잦은 손절이 발생할 수 있다. |
| 과최적화 위험 | 모멘텀 기간, 순위 컷, 이동평균 기간을 많이 튜닝하면 위험하다. 기본 후보는 6개월/12개월, 주간 리밸런싱, 120일 지수 필터처럼 넓은 관행적 구간만 사용한다. |
| 비용 민감도 | 중간. 거래세보다 슬리피지와 리밸런싱 회전율이 핵심이다. |

### 3.2 후보 B: 거래대금 필터 + 중기 모멘텀 + 변동성 조절

| 항목 | 설계 |
| --- | --- |
| 전략 가설 | 한국 시장에서는 거래대금 증가가 정보 반영과 수급 유입을 동반하는 경우가 있다. 중기 모멘텀에 거래대금 지속성을 결합하면 체결 가능성과 신호 품질을 동시에 높일 수 있다. |
| 한국 시장 적합성 | 유동성 부족 종목을 배제하고 체결 실패를 줄이는 데 유리하다. |
| 매수 조건 | 60일 평균 거래대금 기준 상위 20-30%, 3개월/6개월 모멘텀 양수, 최근 거래대금이 과거 60일 중앙값보다 높고 가격이 20일 이동평균 위. |
| 매도 조건 | 모멘텀 음전환, 거래대금 급감, 20일 이동평균 하회, 손절 조건 발생. |
| 리밸런싱 | 주간 또는 격주. |
| 포지션 사이징 | 실현 변동성 목표 비중. 고변동 종목은 자동 축소. |
| 손절/추세 이탈 | ATR 2-3배 손절 또는 20일 저가 이탈. |
| 필요한 데이터 | 일봉 OHLCV, 거래대금, 수정주가, 종목 상태 플래그. |
| 장점 | 거래대금 필터가 비용과 체결 가능성을 직접 개선한다. |
| 약점 | 거래대금 급증이 이미 과열 끝물일 수 있다. 테마주에 노출될 수 있다. |
| 과최적화 위험 | 거래대금 증가율, 모멘텀 기간, 변동성 목표를 동시에 최적화하면 위험하다. |
| 비용 민감도 | 중간 이하. 유동성 필터가 강하면 비용 스트레스에 비교적 강하다. |

### 3.3 후보 C: KOSPI/KOSDAQ ETF 방어형 자산배분

| 항목 | 설계 |
| --- | --- |
| 전략 가설 | 개별 종목 알파보다 시장 국면 회피와 리스크 예산 관리가 실거래 재현성에 더 중요할 수 있다. |
| 한국 시장 적합성 | ETF는 개별 종목 거래정지, 관리종목, 상장폐지 편향 문제를 줄인다. 개인 자동매매가 구현하기 쉽다. |
| 매수 조건 | KOSPI200 ETF, KOSDAQ150 ETF, 단기채/현금성 ETF 중 3개월/6개월 위험조정 모멘텀이 양수인 자산 편입. |
| 매도 조건 | 모멘텀 음수, 지수 120일 이동평균 하회, 포트폴리오 MDD 제한 발동. |
| 리밸런싱 | 월간. |
| 포지션 사이징 | 위험기여도 균형 또는 변동성 목표. 주식 위험자산 총합 70% 이하. |
| 손절/추세 이탈 | 전체 포트폴리오 MDD 10-15% 도달 시 위험자산 축소. |
| 필요한 데이터 | ETF 일봉 OHLCV, NAV/괴리율, 운용보수, 지수 데이터, 현금 금리. |
| 장점 | 가장 구현 가능성이 높고 생존자 편향이 낮다. |
| 약점 | 개별주 전략보다 기대 알파가 작다. ETF 상장 전 기간은 대체 지수로 보강해야 한다. |
| 과최적화 위험 | 낮음. 자산군 수와 룰이 제한적이다. |
| 비용 민감도 | 낮음. 월간 리밸런싱이고 유동성이 좋은 ETF를 사용한다. |

### 3.4 후보 D: 저변동성/퀄리티 팩터 월간 리밸런싱

| 항목 | 설계 |
| --- | --- |
| 전략 가설 | 한국 시장의 고변동·테마주 쏠림을 피하고, 안정적 이익과 낮은 변동성을 가진 종목은 하락장에서 방어력이 높을 수 있다. |
| 한국 시장 적합성 | KOSDAQ의 재무 품질 편차가 크므로 재무 발표일 기준 lag를 엄격히 적용해야 한다. |
| 매수 조건 | 유동성 필터 통과, 최근 12개월 변동성 하위, ROE/영업현금흐름/부채비율 등 품질 점수 상위. |
| 매도 조건 | 품질 점수 하락, 변동성 급등, 유동성 필터 이탈, 관리종목 지정. |
| 리밸런싱 | 월간 또는 분기. |

## 4. 전략 평가 기준

전략은 1차 탈락 조건을 통과한 뒤 점수화한다. 단일 Sharpe Ratio로 선정하지 않는다.

### 4.1 1차 탈락 조건

다음 중 하나라도 해당하면 전략을 폐기하거나 후보군 하위로 내린다.

- 기본 비용 시나리오에서 기대수익이 음수.
- 보수적 비용 시나리오에서 CAGR, Calmar, 월별 안정성이 모두 급격히 붕괴.
- OOS 또는 walk-forward 구간에서 성과 대부분이 사라짐.
- 특정 1-2개 연도 수익이 전체 성과의 대부분을 차지.
- MDD가 동일가중 시장 포트폴리오 또는 KOSPI/KOSDAQ 벤치마크보다 의미 있게 크고 보상 수익이 부족.
- 연간 회전율이 전략 의도보다 과도함. 초기 기준은 ETF/팩터 월간 전략 2회전 이하, 주간 스윙 전략 6회전 이하, 일별 돌파/평균회귀 전략 12회전 이하.
- 실제 주문 금액이 일평균 거래대금 제한을 자주 초과해 부분 체결이 빈번.
- 파라미터를 조금 바꾸면 성과가 바로 무너지는 단일 피크 구조.
- 생존자 편향, 미래 재무정보, 당일 종가 신호-당일 종가 체결이 발견됨.

### 4.2 점수화 체계

| 영역 | 가중치 | 지표 |
| --- | ---: | --- |
| 위험조정 성과 | 25 | CAGR, Sharpe, Sortino, Calmar, 거래당 기대값 |

### 6.3 전처리 원칙

- 모든 신호는 `t`일 장 종료 후 확정된 데이터만 사용한다.
- 주문은 `t+1` 거래일 시가 또는 VWAP로 가정한다. 당일 종가 신호를 당일 종가 체결로 쓰지 않는다.
- 재무 데이터는 공시일 이후 최소 1거래일 lag를 둔다. 공시 시간이 장중/장후인지 알 수 없으면 다음 거래일 이후부터 사용한다.
- 상장폐지 종목이 데이터에서 누락되면 해당 구간의 개별주 전략 결과는 연구용 초안으로만 표시하고 최종 후보 선정에 쓰지 않는다.
- 수정주가는 액면분할, 무상증자, 유상증자 권리락 등 가격 연속성 조정과 현금배당을 포함한 총수익 조정을 분리해 보관한다. 매매 신호는 조정 가격으로 계산하되 체결 가능성, 상한가/하한가, 호가단위는 원가격으로 판단한다.
- 결측 가격, 비정상 거래량, 권리락 조정 오류는 종목별 이벤트 로그로 남긴다.

| 호가 반올림 | 적용 | 적용 | 적용 + 불리한 방향 |
| 부분 체결 | 주문금액 <= ADV 2% | 주문금액 <= ADV 1% | 주문금액 <= ADV 0.5% |

기본 전략은 보수적 비용 시나리오에서 CAGR이 낮아질 수는 있어도 성과 구조가 완전히 붕괴하지 않아야 한다. 특히 거래당 기대값이 비용보다 충분히 커야 한다.

### 6.5 체결 모델

1. 매매 신호 생성: `t`일 종가 이후.
2. 주문 후보 생성: `t+1`일 정규장.
3. 가격 제한 확인: 상한가 매수와 하한가 매도는 실패 또는 부분 체결.
4. 호가단위 반영: 주문 가격을 시장별 tick size에 맞춤.
5. 슬리피지 적용: 매수는 체결가 상승, 매도는 체결가 하락.
6. 유동성 제한: 주문 금액이 ADV 한도를 넘으면 부분 체결.
7. T+2 현금 원장: 보수 모델에서는 매도 대금을 T+2까지 완전 재사용하지 않는다. 브로커가 미수 또는 재매수를 허용하는 경우는 별도 민감도 분석으로 둔다.

### 6.6 검증 방법

- In-sample/OOS: 2010-2018 연구, 2019-2022 검증, 2023-최신 최종 OOS. 단, 데이터 가용성에 따라 rolling split 병행.
- Walk-forward: 3년 학습, 1년 검증을 굴려 파라미터를 고정 또는 제한적으로 갱신.
- Rolling window: 1년/3년/5년 rolling CAGR, MDD, Sharpe, Calmar.
- 국면별 분석: 상승장, 하락장, 횡보장, 급락장.
- 시장별 분석: KOSPI 단독, KOSDAQ 단독, 통합.
- 규모별 분석: 대형, 중형, 소형.
- 파라미터 민감도: 모멘텀 기간, 랭킹 컷, 리밸런싱 주기, 유동성 기준, 지수 필터 기간.
- 비용 민감도: 수수료, 거래세, 슬리피지, 부분 체결률.
- 종목 수 민감도: 상위 10/20/30/50개 편입 및 시장별 위험 예산 변화.
- 리밸런싱 주기 민감도: 주간, 격주, 월간. 단, 최적 주기 하나를 사후 선택하지 않고 사전 후보별 안정성을 비교한다.
- 랜덤 대조군: 동일 유니버스/동일 회전율 조건의 랜덤 진입·청산과 비교.
- 벤치마크 초과성과: KOSPI, KOSDAQ, KOSPI200, 동일가중 시장 포트폴리오, 무위험 현금, buy & hold, 월간 동일가중 리밸런싱.
- 과최적화 보정: Deflated Sharpe Ratio, PBO, bootstrap 신뢰구간, Monte Carlo 경로 재배열, White's Reality Check 또는 유사 다중검정 보정.

## 7. 의사코드

```python
def run_research(config):
    rules = load_market_rules(config.market_rules_path)
    costs = load_cost_schedule(config.cost_schedule_path)

    prices = load_daily_ohlcv(config.price_source)
    actions = load_corporate_actions(config.action_source)
    listings = load_listing_history(config.listing_source)
    flags = load_security_status_flags(config.status_source)
    indices = load_index_data(config.index_source)

    adjusted = build_adjusted_price_table(prices, actions)
    universe = build_point_in_time_universe(
        listings=listings,
        prices=prices,
        flags=flags,
        include_delisted=True,
        exclude_types=["preferred", "spac", "reit", "etf", "etn"],
    )

    benchmarks = build_benchmarks(
        prices=adjusted,
        indices=indices,
        universe=universe,
        cash_rate=config.cash_rate,
    )

    all_results = []
    for strategy_name in config.strategy_candidates:
        for split in make_walk_forward_splits(config.start, config.end):
            train_data = slice_data(adjusted, split.train)
            test_data = slice_data(adjusted, split.test)

            params = choose_allowed_params_without_grid_overfit(
                strategy_name=strategy_name,
                train_data=train_data,
                allowed_param_grid=config.allowed_param_grid[strategy_name],
            )

            signals = generate_signals(
                strategy_name=strategy_name,
                data=test_data,
                universe=universe,
                indices=indices,
                params=params,
            )

            orders = build_rebalance_orders(
                signals=signals,
                rebalance_calendar=config.rebalance_calendar[strategy_name],
                max_name_weight=config.max_name_weight,
                max_equity_weight=config.max_equity_weight,
                volatility_sizing=True,
            )

            fills = simulate_execution(
                orders=orders,
                raw_prices=prices,
                rules=rules,
                costs=costs,
                execution_price=config.execution_price,  # next_open or vwap
                reject_upper_limit_buys=True,
                reject_lower_limit_sells=True,
                adv_participation_limit=config.adv_participation_limit,
                settlement_lag_days=2,
            )

            portfolio = update_portfolio_ledger(
                fills=fills,
                mark_prices=adjusted,
                cash_settlement_lag=2,
                halt_handling="hold_until_tradeable",
            )

            metrics = calculate_metrics(
                portfolio=portfolio,
                benchmarks=benchmarks,
                include_turnover=True,
                include_trade_expectancy=True,
                include_monthly_and_yearly_stability=True,
            )

            robustness = run_robustness_tests(
                strategy_name=strategy_name,
                base_params=params,
                data=test_data,
                costs=costs,
                benchmarks=benchmarks,
            )

            all_results.append({
                "strategy": strategy_name,
                "split": split,
                "params": params,
                "metrics": metrics,
                "robustness": robustness,
                "discard": evaluate_discard_rules(metrics, robustness),
            })

    scorecard = score_strategies(all_results, weights=config.score_weights)
    return make_research_report(scorecard, all_results, benchmarks)
```

## 8. 실험 계획

### 8.1 실험 순서

1. 데이터 무결성 검증
   - 상장/상장폐지 이력, 가격 조정, 거래정지 플래그, 세금 schedule이 준비되지 않으면 개별주 전략 결론을 내리지 않는다.

2. 벤치마크 구축
   - KOSPI, KOSDAQ, KOSPI200, 동일가중 시장 포트폴리오, 현금, buy & hold, 월간 동일가중 리밸런싱을 먼저 만든다.

3. ETF 방어형 전략 검증
   - 가장 실거래 재현성이 높은 기준 전략으로 먼저 돌린다. 이 전략도 비용 반영 후 벤치마크를 방어하지 못하면 개별주 전략의 실거래 기대치를 더 보수적으로 본다.

4. 유동성 상대강도 모멘텀 검증
   - KOSPI와 KOSDAQ을 별도로 검증한 뒤 통합한다.

5. 거래대금+모멘텀 변형 검증
   - 후보 A보다 비용과 체결 안정성이 좋아지는지 확인한다.

6. 저변동성/퀄리티 팩터 검증
   - DART 공시일 lag가 준비된 뒤 진행한다.

7. 변동성 돌파와 평균회귀는 후순위 검증
   - 보수적 비용에서 거래당 기대값이 충분하지 않으면 초기에 폐기한다.

8. 통합 점수화와 모의투자 후보 선정
   - OOS, walk-forward, 비용 민감도, 파라미터 민감도, 실거래 제약을 종합한다.

### 8.2 폐기 기준

- 기본 비용 반영 후 OOS CAGR이 현금 또는 동일가중 벤치마크 대비 의미 있게 낮다.
- 보수적 비용 적용 시 거래당 기대값이 0 이하.
- OOS MDD가 전략 목표를 초과하고 Calmar가 개선되지 않는다.
- rolling 3년 구간의 절반 이상에서 벤치마크 대비 열위.
- 1개 파라미터 조합에서만 성과가 좋고 인접 조합 대부분이 실패.
- 부분 체결 또는 체결 실패가 전체 주문의 20% 이상.
- 소형주·저유동성 종목 제거 시 성과가 대부분 사라짐.
- 데이터 오류 또는 상장폐지 누락을 보정하면 성과가 사라짐.

### 8.3 모의투자 전환 기준

- 기본 비용과 보수 비용에서 모두 기대값이 양수.
- OOS 및 walk-forward에서 성과가 특정 연도에만 집중되지 않음.
- KOSPI/KOSDAQ 또는 규모 구분 중 최소 2개 이상의 독립 구간에서 구조가 유지됨.
- 주문 금액이 유동성 제한을 충족하고 부분 체결률이 낮음.
- 파라미터 민감도에서 넓은 plateau가 확인됨.
- 벤치마크 대비 낙폭 또는 위험조정성과 중 하나 이상이 명확히 개선됨.
- 3개월 이상 소액 모의투자에서 체결가, 슬리피지, 주문 실패율이 백테스트 가정과 크게 다르지 않음.

## 9. 리스크와 한계

- **데이터 품질:** 상장폐지 종목, 거래정지, 관리종목, 권리락, 배당락, 유상증자 조정이 누락되면 성과가 과장된다.
- **미래정보 누출:** 재무 데이터와 지수 편입 정보는 발표일 기준 lag를 적용하지 않으면 사용할 수 없다.
- **체결 문제:** 일봉 데이터만으로 시가 유동성, VI, 부분 체결, 상한가/하한가 잠김을 완전히 재현하기 어렵다.
- **비용 변화:** 세율, 수수료, 공매도 규칙, 호가단위는 바뀔 수 있다. 모든 비용과 시장 규칙은 날짜별 설정이어야 한다.
- **전략 실패 국면:** 모멘텀 전략은 급반전장과 정책 이벤트에 취약하다. 평균회귀는 구조적 하락장에서 손실이 누적될 수 있다. ETF 방어형은 강한 개별주 장세에서 상대적으로 뒤처질 수 있다.
- **소형주 편향:** 한국 시장의 소형주 성과는 체결 가능성을 과대평가하기 쉽다. 유동성 필터와 주문 참여율 제한이 필수다.
- **과최적화:** 후보가 많고 지표가 많을수록 우연히 좋아 보이는 전략이 나온다. 후보 수, 파라미터 범위, 평가 기준을 사전에 고정해야 한다.
- **실거래 전 확인사항:** 브로커 API 주문 가능 시간, 미체결 처리, T+2 현금 재사용 정책, 세금 원천징수 방식, ETF 세금/분배금 처리, 장애 발생 시 수동 청산 절차.

## 10. 최종 결론

1차 연구의 최우선 전략은 **시장 국면 필터 + 유동성 상대강도 모멘텀**이다. 이 전략은 README의 선호 조건인 long-only, 일봉 기반, 저~중간 회전율, 유동성 필터, 시장 국면 필터, 비용 강건성, 설명 가능성, Python 구현 용이성을 가장 균형 있게 만족한다.

동시에 **국내 ETF 방어형 자산배분**을 반드시 함께 검증한다. 개별주 전략이 ETF 방어형 전략보다 실거래 가능성과 위험조정 성과에서 충분히 낫지 않다면, 초기 자동매매 시스템은 ETF 전략을 우선 모의투자 대상으로 삼는 편이 더 보수적이다.

다음 개선 방향은 백테스트 코드 작성이 아니라 데이터 가용성 확인이다. 특히 상장폐지 종목, 거래정지/관리종목 플래그, 권리락/배당락 조정, 공시일 기준 재무 데이터가 확보되지 않으면 개별주 전략의 성과를 최종 판단하지 않는다.
